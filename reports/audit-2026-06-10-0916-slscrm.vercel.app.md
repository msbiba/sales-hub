# Website Audit — slscrm.vercel.app

## Executive Summary
- Pages tested: 9 — `/login`, `/passwort-reset`, `/` (Dashboard), `/pipeline`, `/berichte`, `/kunden/neu`, `/kunden/<id>`, `/nutzer`, `/profil`, plus 404 probe `/does-not-exist`.
- Findings: total 13 (critical 1, high 3, medium 5, low 4).
- Overall grade: **F** (rubric: ≥ 1 critical → F).
- Top 3 must-fix:
  1. **F-001** — Dashboard customer rows are not keyboard-accessible. Customer detail page is unreachable without a mouse — core flow blocker for keyboard / screen-reader users.
  2. **F-004** — Header overflows horizontally below ~800 px (no mobile/tablet menu). Half the app's nav is hidden behind sideways scroll at 375 px and 768 px.
  3. **F-002** — Across every form (login, customer create, profile, password reset, filters) inputs are NOT programmatically labelled. Visual labels are plain `<div>`s, inputs carry no `id` / `aria-label` / `aria-labelledby` / `<label for>`.

## Detailed Findings (per page)

### / (Dashboard)
- Elements exercised: status filter combobox (`Beschwerde` → 3 rows ✓), search textbox (`Huber` → 2 rows ✓), reset filter button, row click (→ /kunden/<uuid> ✓).
- Console: 1 verbose, 0 errors/warnings (raw: `assets/raw/dashboard-network.txt`).
- Network: all 2xx; auth POST 200; 307 redirects only during login flow. No 4xx/5xx, no mixed content, no slow asset.
- Perf (navigation API): TTFB 15 ms, DCL 2566 ms, load 2956 ms.
- Issues: F-001, F-002, F-004, F-010.

### /login + /passwort-reset
- Elements exercised: e-mail + password fill, submit → redirected to `/`. Login works.
- Console: verbose "Input elements should have autocomplete attributes (suggested: current-password)".
- Issues: F-002, F-006.

### /pipeline
- Elements exercised: status combobox, suche, sliders.
- Stats: Offene Angebote 5, Pipeline-Volumen 2.150.000 €, Gewonnen diesen Monat 0. Table 12 rows.
- Issues: F-002, F-011.

### /berichte
- Three charts rendered (status pie, pipeline-status bar, bearbeiter-volumen bar). Charts marked `role=application` with no accessible name / description.
- Bearbeiter chart shows 6 bars for what should be 4 distinct sales reps — same person counted under two labels.
- Issues: F-007.

### /kunden/neu
- Empty submit → inline error messages appear in plain `<p>` text. Fields stay un-marked (no `aria-invalid`), errors not in `[role=alert]` / `[aria-live]`, errors not linked via `aria-describedby`. Status `<select>` lacks `Interessent` option although that status exists in DB.
- Issues: F-002, F-003, F-005, F-009.

### /kunden/<uuid>
- Detail page rich (Stammdaten, Notiz, Aktivität erfassen, Aktivitäten + Historie disclosure groups). Form labels are again non-semantic `<div>`s.
- Issues: F-002.

### /nutzer
- Stats: 6 nutzer, 5 aktiv, 3 rollen. Table + export-csv button + invite button.
- Issues: F-002 (search + rollen-filter).

### /profil
- Issues: F-002, F-006 (two `<input type=password>` w/o `autocomplete`).

### /does-not-exist (404)
- Status 404, page renders English Next.js default "404 / This page could not be found." with no German copy, no back-link.
- Issues: F-008, F-012.

## Recommendations (prioritized)
1. **Critical (now)**
   - Fix F-001: make every customer row a real, keyboard-reachable link. Currently the entire customer-detail flow is mouse-only.
2. **High-impact UX / a11y**
   - Add proper labels & error-association across all forms (F-002, F-003) — this is one refactor (a `<Field>` component) that fixes ~25 inputs across 7 pages.
   - Build a responsive header (F-004). Mobile/tablet users currently see a clipped nav and a horizontally scrolling page.
   - Add `autocomplete` + correct input types (F-005, F-006) — password managers and mobile keyboards rely on it.
3. **Technical / maintainability**
   - Normalise bearbeiter representation (F-007) before more reports are built on top of dirty data.
   - Localise + style the 404 page (F-008) and give every route a real `<title>` (F-012).
   - Reconcile status dropdowns vs the status values that actually exist in the DB (F-009).
